# Code of Conduct

SETU-Swasthya exists to close real gaps in rural healthcare delivery. That
purpose only holds together if the people building it — across the backend,
Flutter, and ML tracks — can collaborate safely and in good faith. This
document, adapted from the [Contributor Covenant](https://www.contributor-covenant.org/version/2/1/code_of_conduct/)
v2.1, sets the baseline for that.

## Our standard

Participants are expected to:

- **Be respectful of disagreement.** Backend, frontend, and ML work here
  moves fast and interlocks tightly (see `CONTRIBUTING.md`'s own "additive
  only" rule) — disagreement about an approach is normal and welcome;
  personal attacks are not.
- **Give and receive feedback constructively.** Critique the code, the
  design, or the decision — not the person. Assume good faith before
  assuming carelessness.
- **Credit work accurately.** Don't claim another contributor's work, and
  don't erase it either — when work from one branch or contributor is
  integrated through a different path (a rebase, a restructure, a squashed
  merge), say so and credit the original author, the way this project's own
  PR history already does.
- **Respect scope and review.** Don't bypass the review/branching discipline
  in `CONTRIBUTING.md` to push through a change unilaterally, and don't block
  others' reasonable work out of territoriality over a module.

Unacceptable behavior includes harassment, discriminatory jokes or language,
personal or political attacks, publishing others' private information
(including a contributor's personal details shared in confidence) without
explicit permission, and sustained disruption of discussions, reviews, or
project spaces.

## A domain-specific addition

This project handles — and is explicitly built toward eventually handling —
real patients' health information. `CONTRIBUTING.md` already states the hard
rule: **no real patient data, ever, anywhere in this repository** (issues,
PRs, commits, test fixtures, screenshots, demo recordings — all of it). This
code of conduct treats a violation of that rule as a conduct matter, not just
a technical mistake: introducing real PHI into a public repository can cause
real harm to a real person who never consented to it. See `SECURITY.md` for
how to report it if it happens.

## Scope

This applies within all project spaces (this repository's issues, pull
requests, discussions, and commit history) and in any other setting where
someone is representing the project or its community.

## Enforcement

Report a violation by emailing **iqraakhan029@gmail.com** with as much
context as you can safely share (this is the actively-maintained contact for
this repository today — update it here as the team formalizes a dedicated
point of contact). Reports are handled with discretion; the reporter's
identity is not shared without their consent.

Maintainers who violate this code of conduct are held to the same standard as
anyone else. Consequences scale with severity and pattern, from a private
warning up to removal from the project's spaces, at the maintainers'
discretion.
